# 마우스 조작 + 첫 튜토리얼 — 설계

2026-09-28 결정. 두 가지를 한 묶음으로 만든다.

- **A. 마우스 조작**: PC에서도 마우스만으로 모든 플레이가 된다. 마우스를 잡아 두지(pointer lock) 않는다.
- **B. 튜토리얼**: 새 캐릭터는 촌장에게 스킬과 물약을 받고, 스킬 등록 → 자동 사용 → 자동 전투를 직접 해 본다.

숲 정화·마을 복구는 별도 설계로 이 다음에 한다.

## A. 마우스 조작

### 무엇이 바뀌나

| | 지금 (PC) | 바뀐 뒤 (PC) |
|---|---|---|
| 마우스 | 월드를 누르면 잠김, 커서 사라짐 | 잠그지 않음, 커서 항상 보임 |
| 이동 | WASD | 왼쪽 아래 가상 패드 (터치와 같은 것) |
| 시점 | 잠긴 마우스 움직임 | 월드를 왼쪽 버튼으로 끌기 |
| 공격 | 왼쪽 클릭 | 월드를 끌지 않고 클릭 한 번 = 한 방, 공격 버튼(누르고 있으면 연타), 자동 전투 |
| 막기 | 오른쪽 버튼 | 오른쪽 버튼 그대로, 막기 버튼 |
| 조준점 | 가운데 + | 없음 |
| 단축키 | 전부 | **WASD만 끔.** Space, Q, 1~3, E, R, J, C, Enter, 메뉴 키(N/V/O/L/K/U/I/B/P/M), Esc 그대로 |

터치 기기는 바뀌지 않는다.

### 구현 단위

- `src/game/render/FpsInput.ts`
  - `requestPointerLock`, `lock()`, `locked`, `lockDenied`, `pointerlockchange/error` 처리를 지운다.
  - 마우스는 항상 지금의 "잠금 거절" 방식: 왼쪽 버튼을 누른 채 끌면 시점, 6px 안에서 떼면 `VirtualFire` 한 번.
  - `moveInput()`에서 KeyW/A/S/D를 뺀다. 가상 패드만 이동을 만든다.
  - `dragToLook` getter는 필요 없어지면 지운다.
- `src/ui/TouchControls.tsx`
  - `isTouchDevice()`는 그대로 둔다 (키 표시 여부에만 쓴다).
  - `TouchStick`의 패드는 모든 기기에서 보인다. 오른쪽 `touch-look` 끌기 영역은 터치 기기에서만 (PC는 월드 캔버스 끌기로 본다).
  - 패드는 마우스로도 끌린다 (이미 Pointer Events라 그대로 동작).
- `src/ui/WorldScreen.tsx`
  - `touch` 하나로 묶여 있던 것을 둘로 나눈다.
    - **배치**: 모든 기기에서 터치와 같은 배치 (패드, 채팅 위치). 별도 플래그 없이 항상 켠다.
    - **키 표시** `keyHints = !isTouchDevice()`: 버튼 모서리의 `<kbd>`, 퀘스트 J, 채널 C, 채팅의 Enter 안내.
  - pointer lock을 걸고 푸는 두 `useEffect`(`uiOpen`에 따라 lock, `pointerlockchange`로 패널 닫기)를 지운다. 패널은 닫기 버튼과 Esc로 닫는다.
  - `document.exitPointerLock?.()` 호출들을 지운다.
  - 조준점 `<div className="crosshair" />`와 그 CSS를 지운다.
- `src/ui/ChatBox.tsx`: PC의 "Enter 채팅" 막대는 그대로 두고, 자리를 패드 위로 옮긴다 (터치와 같은 자리).
- `src/index.css`: PC에도 패드가 보이므로 800×450, 1000×562에서 HUD가 겹치지 않는지 다시 잰다 (패드, 채팅, 스킬바, 물약 설정, 패드 버튼).
- 문구: 시점/공격 안내에 "WASD", "마우스 잠금"이 들어간 문자열이 있으면 5개 언어 모두 고친다.

### 확인

- `?local`에서 PC 마우스만으로: 패드로 이동, 끌어서 시점, 클릭 공격, 버튼 공격(누르고 있기), 막기, 자동 전투, 스킬/물약 칸 누르기와 아래로 끌기, 퀘스트 눌러 찾아가기, 메뉴 열고 닫기.
- 커서가 한 번도 사라지지 않는지, WASD가 움직이지 않는지, 단축키가 되는지.
- 800×450과 1000×562에서 HUD 요소끼리 겹침 0 (지금 쓰는 측정 스크립트).

## B. 튜토리얼

### 대상

- **새로 만드는 캐릭터만.** 캐릭터에 `tutorial` 단계가 있으면 진행 중, 없으면 완료로 본다. 이미 있는 캐릭터에는 없으므로 아무것도 바뀌지 않는다.

### 단계

단계 번호는 서버에 저장하는 값이다.

| 값 | 화면에 뜨는 할 일 | 넘어가는 조건 | 빛나는 곳 |
|---|---|---|---|
| 0 | 촌장에게 말을 거세요 | 촌장과 대화 (서버 검사) | 촌장 줄 자체 (누르면 촌장에게 걸어감) |
| 1 | 스킬 창을 열어 받은 스킬을 1번 칸에 끌어 놓으세요 | 스킬 창에서 스킬을 칸에 놓음 | 메뉴 버튼 → 스킬 버튼 → 1번 칸 |
| 2 | 스킬 칸과 물약 칸을 아래로 끌어 자동 사용을 켜세요 | 스킬 1이 든 칸과 물약 칸이 둘 다 자동 | 스킬바 |
| 3 | 자동 전투 버튼을 눌러 보세요 | 자동 전투가 켜짐 | 자동 버튼 |
| (없음) | 끝. "준비 끝! 촌장의 첫 부탁을 확인하세요" 배너 후 퀘스트 1로 | | |

- 할 일 줄은 퀘스트 칸 자리(미니맵 아래)에 뜬다. 튜토리얼 중에는 퀘스트 칸 대신 보인다.
- 건너뛰기는 없다 (2026-09-28 결정: 처음 만든 캐릭터는 모두 튜토리얼을 거친다).
- 막지 않는다: 튜토리얼 중에도 사냥, 이동, 메뉴가 전부 된다.
- 빛나는 곳은 해당 요소에 CSS 클래스 `tutorial-glow`를 붙인다 (테두리가 천천히 밝아졌다 어두워짐). 메뉴가 접혀 있으면 메뉴 버튼이, 펼쳐지면 스킬 버튼이 빛난다.

### 보상

- **0 → 1 (촌장 대화)**: 스킬 1을 배우고 작은 물약 5개.
- **3 → 끝**: 골드 100.

### 시작 상태 변경

- 새 캐릭터의 가방: 지금 `{ potion_small: 3 }` → `{}`. 물약은 촌장에게 받는다.
- 스킬 1은 배우기 전엔 쓸 수 없다. 스킬 창에서 스킬 1은 "촌장에게 배우기"로 잠겨 보이고, 끌 수 없다.
- 스킬바는 직업마다 계정 전체에 저장되므로(`controls.hotbars`) 이미 스킬 1이 1번 칸에 있을 수 있다. 튜토리얼 캐릭터가 스킬 1을 아직 안 배웠으면 그 칸은 빈 칸처럼 보인다. 1단계는 "칸에 놓는 행동"을 조건으로 해서, 이미 들어 있어도 한 번 끌어 놓아야 넘어간다.
- 2단계가 시작될 때 화면이 자동 사용을 끈다: 스킬 1이 든 칸의 `autoSkills`와 `autoPotion`. 그래야 "아래로 끌어서 켜기"가 켜기가 된다 (지금 기본값이 스킬 1 자동 켜짐이라, 그대로 두면 끌기가 끄기가 된다).
- 자동 전투는 배우지 않은 스킬을 쓰려 하지 않는다.

### 서버

- `Character`에 `tutorial?: number` (0~3). 없으면 완료. `createCharacter`는 `tutorial: 0`.
- `readCharacters` (`src/game/account/characters.ts`)는 `tutorial`을 0~3 정수만 받고 그 밖은 없는 것으로 (= 완료) 읽는다.
- 월드 입장 때 방의 내 상태 `look`에 `learned: boolean`(스킬 1을 배웠는지)을 싣는다. `useSkill`은 `learned === false`이면 슬롯 0을 `unavailable`로 거절한다. 다른 슬롯은 레벨/전직 조건 그대로.
- 엔드포인트
  - `tutorialTalk()`: 월드 안, `requireNpc("elder")`, 단계가 0일 때만. 물약 5개를 가방에, 단계 1, 방 상태 `learned: true`. 다른 단계면 아무것도 안 하고 현재 상태를 돌려준다 (두 번 눌러도 한 번만).
  - `tutorialStep(from)`: 단계가 `from`(1 또는 2)일 때만 `from + 1`로. 보상 없음.
  - `tutorialFinish()`: 단계가 3일 때만. 골드 100, `tutorial` 지움.
  - 모두 `withProfileLock` 안에서 읽고 쓴다. 응답은 지금 가방 응답(`bagView()`의 `BagView`)에 `tutorial` 필드를 더한 것.
- 1~3단계는 원래 이 기기의 설정(스킬바, 자동 켜기)이라 화면이 확인하고 서버에 알린다. 보상은 끝의 골드 100뿐이고 캐릭터마다 한 번이라, 속여도 튜토리얼을 제대로 한 것과 같다.

### 화면

- `src/ui/TutorialTracker.tsx` (새 파일): 현재 단계의 할 일 줄. `QuestTracker` 자리에 대신 그린다.
- 단계 판정은 `src/game/account/tutorial.ts` (새 파일)의 순수 함수로: `tutorialStepDone(step, { droppedSkill, autoSkillOn, autoPotionOn, autoBattle })`. 화면은 이것으로 넘어갈 때를 정하고 서버를 부른다. 서버와 화면이 같은 단계 상수를 쓴다.
- 촌장에게 말 걸기(`onTalk("elder")`): 단계 0이면 `tutorialTalk()`를 부르고, 퀘스트 창 대신 촌장의 튜토리얼 대사(스킬과 물약을 줬다)를 보여 준다.
- `SkillPanel`의 `drop`이 성공하면 "스킬을 칸에 놓음" 사건을 알린다.
- 끝나면 지금 퀘스트 완료 배너와 같은 배너로 "준비 끝!"을 보여 준다.

### 문구

5개 언어(ko, en, ja, zh-Hant, zh-Hans)에 단계별 할 일, 촌장 대사, 끝 배너, "촌장에게 배우기". 800×450에서 할 일 줄이 두 줄을 넘지 않는지 잰다.

### 테스트

- 서버 (`npm run server:test`)
  - 새 캐릭터는 `tutorial: 0`, 가방 비어 있음, 스킬 슬롯 0 사용 거절.
  - `tutorialTalk`: 촌장에게서 멀면 `not_near`; 가까우면 물약 5개와 단계 1, 스킬 0 사용 가능; 두 번 불러도 물약 5개.
  - `tutorialStep`: 단계가 다르면 그대로; 앞으로만 간다.
  - `tutorialFinish`: 3단계에서만 골드 100, 한 번만.
  - `tutorial`이 없는 기존 캐릭터: 스킬 0 사용 가능, 튜토리얼 엔드포인트가 아무것도 안 함.
- 화면 (`npx vitest run`): `tutorialStepDone` 단계별 판정.
- `?local`에서 새 캐릭터로 처음부터 끝까지. 5개 언어로 할 일 줄 길이.
