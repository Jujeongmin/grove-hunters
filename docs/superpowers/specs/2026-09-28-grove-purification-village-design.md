# 숲 정화 + 마을 복구 — 설계

2026-09-28 결정. 서버(월드) 하나에 모인 사람들이 함께 숲을 정화하고, 그 보답으로 마을을 다시 짓는다.
같은 서버의 모든 채널이 하나의 기록을 함께 채운다.

## 1. 흐름과 수치

하나의 흐름: 사냥 → 숲 정화도가 오름 → 단계마다 보상과 세상 변화 → 2단계마다 마을 건물 터가 열림 →
기부로 건물 완공 → 서버 전체가 영구 혜택.

### 숲 정화 (한 주마다 다시 오염)

- 한 주: **월요일 0시(한국 시간, UTC+9)** 부터 다음 월요일 0시 전까지.
- 서버마다 이번 주 **처치 수**를 센다. 모든 사냥터(숲 필드 1·2, 깊은 숲, 보스 구역)의 모든 처치가 1씩.
- 목표 **주당 3,000마리** (`PURIFY_GOAL`, 서버마다 같음). 정화도 = min(1, 처치 수 / 3,000).

| 단계 | 정화도 | 세상 변화 | 보상 |
|---|---|---|---|
| 1 | 30% | 마을과 숲 필드 1에 꽃이 더 핌 (`sn_flowers`, `sn_bush_flowers`) | 이번 주 사냥한 사람 모두 골드 200 |
| 2 | 60% | 하늘과 안개가 맑아짐 | 마을 건물 터 하나가 열림 (한 주에 1개, 모두 4개). 네 채가 다 지어진 뒤로는 골드 300 |
| 3 | 100% | 숲 필드 1의 채널마다 **정화의 수호자**가 나타남 | 이번 주 사냥한 사람 모두 골드 500. 수호자를 잡은 사람은 수호자 보상 |

- "이번 주 사냥한 사람": 이번 주에 그 서버에서 몬스터를 한 마리라도 잡은(보상을 받은) 계정.
- 보상은 **다음에 구역에 들어올 때** 자동으로 받는다 (접속 중이면 다음 포탈 이동이나 재접속 때).
- 수호자(`grove_guardian`): 버섯왕 모델을 0.7배로 줄여 쓴다. 레벨 12, 체력 8,000, 공격 30. 채널 방마다 한 마리,
  그 주에 다시 나오지 않는다. 보상: 경험치 3,000, 골드 500~800, 큰 물약 3, 포자 1.

### 마을 복구 (영구)

- 마을에 **건물 터 4곳**이 정해져 있다 (마을 지도의 빈 땅, 구현 계획에서 칸을 고른다).
- 터 4곳에는 처음부터 통나무·바위 더미(`pt_logs`, `pt_rock`)가 놓인 막힌 땅이다(지도가 주마다 바뀌지 않게). 열리면 더미 위에 "짓는 중 n%" 이름표가 뜨고, 완공되면 집 모델로 바뀐다.
- 건물은 정해진 순서로 하나씩 짓는다. 열린 터가 있고 앞 건물이 끝나야 다음 건물에 기부할 수 있다.

| 순서 | 건물 | 모델 | 필요한 것 | 서버 혜택 (영구) |
|---|---|---|---|---|
| 1 | 약초상 | `bld_house_small` | 젤리 300, 골드 20,000 | 상점 물약 값 -20% |
| 2 | 훈련소 | `bld_house_long` | 강화석 200, 거미줄 150, 골드 40,000 | 사냥 경험치 +5% |
| 3 | 여관 | `bld_house_tall` | 핵 150, 골드 60,000 | 쓰러질 때 잃는 경험치 절반 |
| 4 | 망루 | `bld_tower` | 포자 30, 핵 100, 골드 100,000 | 미니맵에 보스·수호자 표시 |

- 기부: **촌장 대화의 "기부하기"** 로 연다. 재료(가방에서)와 골드를 원하는 만큼 넣는다. 필요한 양을 넘는 몫은 받지 않는다.
- 기여 점수: 골드 1 = 1점, 재료 1개 = 그 재료의 판매가(`sellPrice`)만큼.
- 완공되면 건물 위에 **기여 상위 3명의 이름**이 떠 있다 (NPC 이름표 방식). 기부할 때의 캐릭터 이름을 쓴다.
- 완공 보상: 기부자마다 점수의 20%를 골드로, 점수만큼 경험치를 받는다 (다음 입장 때).

수치(`PURIFY_GOAL`, 단계 보상, 건물 재료)는 실제 인원을 보고 조절한다. 모두 `grove.ts` 한곳에 둔다.

## 2. 구조

### 공용 규칙 `src/game/world/grove.ts` (서버와 화면이 같이 씀)

- 상수: `PURIFY_GOAL`, `STAGES`(30/60/100%와 단계 보상 골드), `BUILDINGS`(순서·id·모델·필요한 것·혜택), `SITES`(터 4곳의 칸).
- `weekOf(now): string` — 한국 시간 기준 주 번호 (예: `"2026-W40"`, 월요일 시작).
- `stageOf(kills): 0 | 1 | 2 | 3`, `purity(kills): number`.
- `readGrove(raw)`, `readVillage(raw)` — 저장값을 믿을 만큼만 읽고, 이상하면 기본값.
- `donation(village, building, offer, bag, gold)` — 받을 양(필요한 만큼으로 줄인 것), 점수, 완공 여부. 순수 함수.
- `completionRewards(donors)` — 기부자별 골드·경험치.
- 혜택: `potionPriceFactor(village)`, `huntXpFactor(village)`, `deathLossFactor(village)`, `revealsBosses(village)`.
- 뷰 타입 `GroveView` (화면이 받는 것).

### 서버 저장 (서버마다, 공용 컬렉션: 지금 랭킹과 같은 방식)

- `grove` 항목 (서버당 1개): `{ world, week, kills, paid (0~3), lastWeek: { week, paid } | null }`.
- `village` 항목 (서버당 1개): `{ world, open (0~4), buildings: { [id]: { given: { gold, items }, donors: { [account]: { points, name } }, done } } }`.
- 계정 상태 `grove: { [world]: { week, hunted, claimed, lastWeek: { week, claimed } | null, pending: { gold, xp } } }`.
- 방 상태 `groveKills`: 아직 합치지 않은 처치 수.

### 서버 기능

- `grove(): GroveView` — 정화도, 단계, 남은 날짜, 터와 건물 진행, 건물별 상위 3명, 혜택.
- `donate(building, items, gold): GroveView` — 촌장 옆에서만 (`requireNpc("elder")`).
- 입장(`arrive`)할 때: 받을 단계 보상과 완공 보상을 지급하고 알림을 보낸다.
- 방 틱: 10초마다 방의 `groveKills`를 `grove`에 합친다. 3단계인 주에는 숲 필드 1 방이 수호자를 소환한다.

### 화면

- 메뉴에 **숲** 버튼(아이콘은 PixelLab으로 496 RPG icons 색에 맞춰 만든다) → `GrovePanel`:
  이번 주 정화 게이지(처치 수 / 3,000), 단계 3개, 남은 날짜, 건물 4채의 상태(닫힘/짓는 중 진행률/완공과 혜택), 상위 기여자.
- 촌장 대화의 선택지에 **기부하기** 추가 → `DonatePanel`: 지금 짓는 건물의 필요한 것, 가방 재료와 골드 입력, 기부.
- 월드: 단계 1이면 꽃을 더 심고, 단계 2면 하늘과 안개를 맑게, 열린 터에 더미, 완공된 터에 건물과 이름표.
- `grove()`는 "숲" 패널을 열 때, 구역에 들어올 때, 그리고 1분마다 부른다.

## 3. 데이터 흐름

1. **처치**: `reward()`에서 방 상태 `groveKills`에 처치 수를 더한다. 보상을 받는 계정은 계정 상태의
   `grove[world].week`가 이번 주가 아닐 때만 `{ week, hunted: true, claimed: 0 }`로 쓴다 (한 주에 한 번 쓰기).
2. **합치기 (10초마다)**: 방 틱에서 `groveKills > 0`이고 마지막으로 합친 지 10초가 지났으면, 서버 잠금 안에서
   `grove`를 읽고 → 주가 바뀌었으면 `lastWeek`에 지난주를 옮기고 초기화 → 처치를 더하고 → 새 단계를 계산한다.
   2단계를 이번 주 처음 넘으면 `village.open`을 1 올린다 (4 넘지 않음). 쓰고 나서 방의 `groveKills`를 0으로.
3. **단계 보상**: 입장할 때, 계정의 이번 주(또는 지난주) 기록이 사냥함이고 `claimed < paid`면 모자란 단계의
   골드를 주고 `claimed = paid`. 2주 넘게 지난 몫은 없다.
4. **수호자**: `grove.paid`가 3인 주에, 숲 필드 1 방은 몬스터를 읽을 때 수호자가 없고 이번 주에 잡힌 적이 없으면 소환한다.
   잡히면 방 상태에 이번 주 번호를 적어 다시 나오지 않게 한다.
5. **기부**: 촌장 옆 → 잠금 안에서 `village` 읽기 → 지금 짓는 건물인지 확인 → `donation()`으로 받을 양 계산 →
   골드를 먼저 빼고, 캐릭터 가방에서 재료를 빼고, `village`에 더한다. 중간에 실패하면 골드를 돌려준다.
   완공되면 `completionRewards()`로 기부자마다 계정 상태 `pending`에 보상을 적는다.
6. **혜택**: 서버는 `village`를 서버별로 30초 기억해 두고 `buyItem`(물약 값), 사냥 경험치 지급, 쓰러질 때 잃는
   경험치에 적용한다. 미니맵 표시는 화면이 `GroveView`로 그린다.

## 4. 오류 처리

- **동시 쓰기**: `grove`와 `village`는 서버마다 잠금 하나(`withGroveLock(world)`, 지금 친구 잠금과 같은 방식) 안에서만 읽고 쓴다.
- **잃을 수 있는 것**: 방이 갑자기 꺼지면 합치지 않은 처치가 최대 10초치 사라진다. 혜택은 최대 30초 늦게 적용된다. 둘 다 받아들인다.
- **중복 지급 없음**: 단계 보상은 계정의 `claimed`로, 터 열기는 한 주에 1개로, 수호자는 방의 주 번호로, 완공 보상은 `pending`을 지급하고 비우는 것으로 한 번만.
- **기부 검사**: 촌장 옆, 지금 짓는 건물, 정수 수량, 가방에 실제로 있는 것, 가진 골드 안. 필요한 양 넘는 몫은 받지 않는다. 골드는 먼저 빼고 실패하면 돌려준다.
- **깨진 기록**: `readGrove`, `readVillage`, 계정의 `grove` 읽기는 이상한 값을 기본값으로 읽는다.
- **불러오기 실패**: 패널에 "불러오지 못했어요". 게임은 계속된다.
- **부계정**: 단계 보상은 계정마다 직접 사냥해야 받으므로 따로 막지 않는다.
